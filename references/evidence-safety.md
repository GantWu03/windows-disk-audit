# 证据与安全规则

## 不变量

1. 默认只读；排查和清理分开。
2. `Cache`、`Temp`、`Logs`、`.tmp`、`.bak`、旧日期和大体积都只是线索。
3. 来源、用途、影响任一不明时，保留并继续调查。
4. 权限不足不等于为空，也不允许为清理而使用 `takeown`、`icacls` 夺取系统目录权限。
5. 清理时不得使用未解析变量、通配符或相对路径；先记录规范化绝对路径并验证仍在授权范围内。
6. 检查重解析点、联接、符号链接、挂载点、硬链接、稀疏和压缩文件，避免跨盘或重复计量。
7. 空间进入危险区时不启动新的高写入工作，把报告、隔离和备份放到其他盘；未经授权不终止已有进程。脚本默认门禁为 5 GiB，可按环境设得更严格。
8. “可重下”不等于“值得清”：比较释放量、重下载流量、重建时间、离线能力和复发速度。
9. 单一负面证据不证明不存在依赖；“某处没找到引用”不能单独升级为孤儿或可删除。
10. 权限失败、超时和部分扫描只能得到未知或下界，不能得到 0、很小或无影响。

## 通用证据

按结论的重要性选择证据。路径、大小口径、扫描完整性通常是基本事实；最近写入、生成者、进程/服务、安装注册、文件类型、官方管理方式和删除影响，应在它们能够改变建议时继续核验。不要为了让低收益对象字段齐全而逐项采集所有证据，也不要因已有模板没有某个字段而放弃更有价值的专用证据。

推荐只读方法：

```powershell
# 容量基线
Get-CimInstance Win32_LogicalDisk -Filter "DeviceID='$env:SystemDrive'" |
  Select-Object DeviceID,Size,FreeSpace

# 文件或目录元数据；不要把 Length 当作目录大小
Get-Item -LiteralPath <精确路径> -Force |
  Select-Object FullName,Length,CreationTimeUtc,LastWriteTimeUtc,Attributes,LinkType,Target

# 当前进程路径
Get-CimInstance Win32_Process |
  Select-Object ProcessId,Name,ExecutablePath,CommandLine

# 疑似重复文件：先比较长度，再哈希
Get-FileHash -Algorithm SHA256 -LiteralPath <文件1>,<文件2>

# MSI/程序登记只用于归属核对，不代表文件一定可删
Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*',
  'HKLM:\Software\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*' -ErrorAction SilentlyContinue
```

子 Agent先取得本机事实。对产品归属、易变系统行为、厂商目录、受支持清理方式、命令范围和删除影响，优先查找 Microsoft 或产品官方文档并记录链接、访问日期和资料实际支持的结论；官方资料不存在、无法访问或没有回答当前问题时，再使用专用工具、可靠一手资料或明确标注的推断。低收益且外部资料不会改变结论时无需为了形式联网。主 Agent只在裁决跨章节矛盾时自行补查；无法联网时降低依赖外部资料的结论强度。

## 调查结论与矛盾裁决证据

负责目录的子 Agent必须核验“该怎么处理以及会发生什么”，不能只核验对象存在。它应优先深入会影响用户决策的高收益、高风险、用户点名或涉及状态变更的对象，并按需要检查：

- 建议依据：先用自然语言明确做什么、不做什么、是否值得现在做，再解释为什么不采用整目录删除、手删或更激进方案。
- 方法依据：优先使用 Windows、应用、包管理器或虚拟化工具支持的方法，并核对真实作用范围。
- 影响依据：先说明当前已安装软件、现有项目、设置/登录/用户数据是否受影响，再说明重下载或重建成本、离线影响和是否会很快复发。
- 验证与恢复：写明处理前检查、处理后如何确认空间和功能、失败后怎样恢复。
- 新增证据：寻找能直接支持或推翻结论的独立证据；高风险或软件管理动作优先使用官方文档、产品 CLI/list/dry-run、配置、注册或签名。低收益保留项不要求为了形式补证。
- 可回收量：非零范围必须有证据直接支持；对 Installer、系统组件、数据库、虚拟盘等受保护对象，重复哈希、相同大小或未发现引用都不能换算为收益，必须采用官方或产品专用工具认可的范围。

上述内容是思考清单，不是固定输出字段；可以合并成自然解释。一个对象不相关的方面无需强行展开。同一路径的第二次大小测量、同一句事实的换写、空泛的“复核通过”都不能单独支持结论。官方链接一旦引用，就应实际打开并核对适用产品和支持的具体结论；搜索摘要和凭记忆构造的 URL 不算证据。

主 Agent不逐项重复上述调查。只有不同子 Agent对同一对象产生矛盾时，主 Agent才使用同样的证据标准核实并裁决；单个章节证据不足则退回负责 Agent补充或保留不确定性。

## 大小与对比

- 目录扫描总和是估算；权限失败、硬链接、稀疏、压缩、去重和虚拟盘会改变口径。
- 对比同一工具、同一权限、相近时间点的结果。
- 记录“当前占用”“预计可回收范围”“清理后实际释放”；三者不得互换。
- 对异常增长至少做两个时间点采样，记录相关活动；一次快照不能证明增长来源。
- 同一对象被父目录和子目录同时报告时，只计一次。
- 预计收益分为立即、条件、理论和未知；只有负责目录的子 Agent给出直接依据，且合并时不存在未解决矛盾的立即收益才能进入合计。

## 风险等级

- 高：系统组件、安装维护缓存、用户原始数据、活动数据库、虚拟磁盘、恢复数据、来源未知对象。不得直接删除。
- 中：需要系统/应用自身清理、卸载、迁移或会产生明显重建成本的对象。逐项授权。
- 低：本次任务明确创建的临时文件，或已确认由关闭应用生成、无状态、可安全重建的缓存。仍需路径核验和授权边界。
- 未知：用途不明、证据冲突、权限不足。保留。

## 专门证据规则

### Windows 系统与安装维护

- `WinSxS`、驱动仓库、Installer、WindowsApps 和 System32 不手删。
- 对系统维护或安装缓存，“注册表未引用”最多形成调查线索；不得据此移动、隔离或计算可释放量。
- 休眠、分页、交换文件只用 Windows 设置管理，并说明快速启动、崩溃转储、稳定性和重启影响。
- Windows Update/Installer 活动、BITS 状态或待重启存在时，只记录下载和暂存，不清。
- 崩溃转储和日志清理前确认用户不再需要故障定位。

### SQLite、WAL 与其他活动数据库

- 主库、`-wal`、`-shm` 是一致性集合；WAL 可能含已提交但未写回主库的数据。
- 应用运行中不移动、删除或“修复”数据库。优先使用应用导出、维护功能或数据库在线备份。
- 必须离线处理时，先退出应用、确认无相关进程、完整保留文件集合并验证副本可打开。

### Docker、WSL 和虚拟磁盘

- 不直接删除、截断或覆盖 VHD/VHDX、发行版目录、虚拟机磁盘和 Docker volume。
- 命名卷可能是唯一数据库；“无运行容器引用”不等于无价值。
- WSL 迁移采用导出、验证、再注销；注销是破坏性操作。
- 快照、检查点和差分磁盘有父子依赖，不能单独删。
- 大范围 prune 命令不能代替逐项说明和授权。

### Git worktree

至少检查：`git worktree list --porcelain`、当前分支、独有提交及远端状态、已跟踪/未跟踪/忽略文件、子模块、LFS、嵌套仓库和锁定状态。

“很久没动”“状态干净”“已经提交”均不足以证明可删除。确认后使用 Git worktree 管理命令，不直接递归删目录。

### 用户数据、应用状态和缓存

- Desktop、Downloads、Documents、媒体、项目和云同步目录按用户数据处理。
- 浏览器或应用 `User Data`、Profile、Application Data 可能包含登录、扩展、草稿和离线资料，不能整删。
- 消息应用媒体可能是用户唯一副本，不因位于 Cache 子目录就自动清理。
- 优先治理缓存位置、上限和日志轮转；反复清空可能只有短期收益。

### 回收站与隔离

回收站是恢复层，不是默认缓存。清空需单独授权。用途不完全确定的普通文件可在用户授权后移到其他盘隔离并记录原路径、大小、时间和恢复位置；系统文件、活动数据库和虚拟磁盘不适用。

## 清理前后门禁

执行前必须重新确认：精确路径、最新写入、应用已由用户关闭、目标不是链接/挂载点/虚拟盘容器、隔离盘容量足够、恢复方式可行。一次只用一种文件操作工具，不跨 Shell 传递待删路径。

执行后检查：目标处理结果、系统盘实际释放、相关应用/服务/项目能否正常使用、缓存是否立即重建、是否留下复制副本或失败残留。估算不能代替实测。

## 典型错误

- “WAL 比主库大，只删 WAL。”——可能丢最新提交。
- “两个 WindowsApps 版本相近，是重复安装。”——可能是框架、资源包或依赖。
- “VHDX 很久没改，可以删。”——宿主时间不能证明内部数据无用。
- “worktree 已提交，可以删。”——提交可能未推送，忽略文件可能是唯一数据。
- “权限不够，先取得所有权。”——权限本身就是风险边界。
- “更新缓存清完又长，继续删。”——更可能说明更新任务仍在运行。
