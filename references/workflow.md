# 调查工作流

本文件给协调者使用。它规定推进顺序和判断方法，不规定唯一工具、固定调查数量或固定输出字段。安全边界是硬门禁；调查深度应随收益、风险、用户关切和证据变化。

## 阶段 0：范围与容量基线

确认目标盘、输出目录、允许与排除范围、时间预算和只读状态。建议用 `scripts/new_audit_manifest.ps1` 保存清单，再用 `scripts/collect_inventory.ps1 -Phase baseline` 取得容量与根一级粗测。

通过条件：范围明确、输出位置安全、没有执行清理授权。空间进入危险区时，Agent 不启动新的高写入活动和无目标全盘扫描，报告放到非系统盘；不自行终止已有进程。5 GiB 是脚本可调整的保守默认写入门禁，不是所有设备的最优常数。

## 阶段 1：从全局缩小到短名单并确定分工

先列举，再对根一级和通用候选限时粗测。`complete_logical` 是完整逻辑大小；`partial_lower_bound` 只是已读到的下界。它们都不等于磁盘实际占用或可回收量。

用以下问题决定先查什么：

1. 它是否正在增长、引发崩溃或与用户问题直接相关？
2. 可能回收或迁移的空间是否足以改变用户决策？
3. 来源和处理方式是否能被可靠核验？
4. 误判会不会伤及系统、数据、项目或恢复能力？
5. 继续调查的成本是否值得？

优先级标签可用但非必需。不要为了让所有对象符合统一分级而降低解释质量。若一个大头已经解释主要异常，可以围绕它继续；若低收益项不会改变建议，可以合并记录或停止。

在启动任何子 Agent 前，根据本机基线一次性形成 `cluster-plan`。计划至少写明每个目录簇的负责路径、边界、分组理由、相关操作卡和输出位置。分组规则是：

- 显著的大目录原则上一个子 Agent负责，保证能在同一上下文中追完内部大头；
- 多个较小目录按生成者、用途或处理方式合并，避免一个小目录一个 Agent；
- 同一应用分散在 Program Files、ProgramData、Local 和 Roaming 的数据尽量由同一 Agent统一解释；
- 只有大目录内部明显异质，或 Installer、虚拟磁盘等对象需要完全不同的专用方法时才进一步拆分；
- 通用 Windows 地图只是发现入口，不固定 Agent 数量。本机不存在的类别不创建任务，固定清单之外的大头也必须纳入计划。

基线中达到本次“大目录”标准的每个一级对象必须在 `cluster-plan` 中有明确去向：分配给一个目录簇，或因权限、预算、排除范围等原因列入计划盲区并说明理由。不得因为对象不在通用清单、测量超时或用途未知而静默跳过。分工以路径不重叠、覆盖清楚和解释连贯为完成条件，不以增加 Agent 数量为目标。

## 阶段 2：按计划并行调查

按 `cluster-plan` 下发互不重叠的只读任务。只要软件允许且安全门禁没有阻止，可以使用软件提供的并行上限；Skill 不另设更低的固定并发数。平台没有子 Agent或无法并行时，按同一计划串行执行，而不是改回固定三路模板。

子 Agent对负责路径内的调查完整性和结论负责：取得局部事实、解释生成者与用途、标出活动状态、核验处理方式和影响，并直接写成用户可读章节。它在负责目录内发现新的重大子项时应继续下钻，因为这属于原定范围；只有目标落入其他 Agent路径或授权范围之外时才停止跨界并记录。不得执行变更，也不得把未核实推测包装成最终结论。

子 Agent先以本机证据确认对象和活动状态；遇到产品归属、受支持维护方法、命令范围、删除影响或易变行为时，优先查找 Microsoft 或产品官方资料。引用时记录链接、访问日期和实际支持的结论。官方资料不可用或没有回答当前问题时，才使用专用工具、可靠一手资料或明确标注的推断，并相应降低确定性。低收益且不会改变结论的对象无需为了形式联网。

目录内通常使用 [目录级操作手册](directory-procedures.md) 的思路：确认边界，一层拆分，深查少数大头，识别生成者与活动状态，再判断用途和处理影响。专用 CLI、应用配置、注册信息或更准确的只读工具能够更直接回答问题时，可以替代通用步骤。

每个目录簇固定返回三个产物：`findings.json` 保存该簇已经形成的全部候选，`coverage.json` 保存检查路径、扫描状态、超时、权限和盲区，`chapter.md` 直接面向用户解释该簇。候选标准在分派任务时根据本次范围和收益阈值确定；不是每个文件都入选，但一旦入选，后续不能因低收益被无声丢弃。

`chapter.md` 以真实目录层级为主线，而不是以“建议删除”“建议保留”分类。对每个有意义的对象，用自然段说清它是什么、由什么活动产生、当前处理选择、不同选择会影响什么，以及仍缺哪些证据。建议是供用户权衡的选项，不是替用户作出的决定。低收益项可以更短，但不能只写一个动作词。

## 阶段 3：无损合并与矛盾裁决

先用 `scripts/merge_findings.ps1` 将各目录簇的候选和覆盖记录无损合并，并保留全部 `chapter.md`。该步骤不做重要性筛选，也不把父目录结论当作子目录结论。子 Agent返回后，主 Agent只做四件事：

1. 根据已去重的数据生成置于报告开头的浅层空间概况。
2. 修正父子目录重复计量，并用后续非重叠子目录测量更新父目录的已知下界。
3. 合并真正相同的重复对象，保留一个完整解释和全部 `source_refs`。
4. 识别并裁决不同子 Agent对同一对象产生的真实矛盾。

主 Agent不得按重要性筛除候选，也不对所有子 Agent结果做常规事实复核。除真正重复、父子计量修正和已裁决矛盾外，不得改写、摘要、简写或压缩子 Agent章节。只有生成者、对象性质、处理方式和影响均相同的项目才算真正重复；合并时保留其中一份完整解释和全部 `source_refs`。

只有子 Agent结论互相矛盾时，主 Agent才深入核实并裁决。裁决应尽量回答：

- 它实际是什么、由谁在什么场景产生？
- 当前是否仍被使用，哪些本机证据支持这一点？
- 建议用户现在具体做什么，哪些做法不应采用，是否值得？
- 该方法准确作用于什么，不会处理什么？
- 当前软件、项目、账号、设置和数据会怎样？未来是否重下载、重建或复发？
- 结论依据是什么，还有什么不确定？

这些是调查问题，不是必须逐栏填写的表格。可以用一段连贯解释同时回答多个问题；不相关的问题无需制造答案。

主 Agent应主动寻找能直接解决冲突的独立依据，而不是重复测量目录大小。联网与否由它判断：产品行为、官方维护方式、命令范围或版本信息不稳定且会影响裁决时适合联网；本机事实已足够时无需联网。外部依据优先官方和一手资料，记录其实际支持的结论。没有跨章节矛盾但单个章节证据不足时，退回原子 Agent补充或保留不确定性，不由主 Agent重新调查。

子 Agent在覆盖记录、发现记录或章节中明确写出的盲区、未知、抽样边界和权限失败必须随章节进入最终正文。主 Agent只有在裁决真实矛盾并取得足以解决不确定性的新证据时才能更新；否则不得把“不确定比例”“尚未映射”“部分扫描”等改写为确定归属或确定影响。

以下结论需要更高证据门槛：直接清理、卸载、迁移、系统设置变化、非零可回收量，以及系统组件、安装修复源、数据库、虚拟磁盘和用户数据的处理建议。证据不足时降低结论强度，说明下一步，而不是补齐模板。

## 阶段 4：小项与盲区

只有主要大头已经解释后再做。可从本次收益阈值附近的单项开始，再按生成者聚合更小分片；100 MiB–1 GiB 仅是常见示例。满足任一条件即可停止：

- 连续两个目录簇没有改变行动顺序；
- 新发现低于本次有意义收益；
- 达到时间预算；
- 权限、超时或扫描成本已经超过潜在收益。

停止不代表“没有其他占用”。补查产生的新候选追加到合并集合；停止只能结束继续发现，不能删除已经形成的候选。覆盖记录说明未查范围或抽样边界，这里不设固定覆盖率和条目数。

## 阶段 5：目录报告与检查

主 Agent按 [报告指导](report-format.md) 完成报告。开头放“主要空间去向”概览表，列出主要对象或目录、占用口径和用途；正文直接使用 `merged/chapters.raw.md` 中的子 Agent章节。只允许定点删除真正重复的段落、修正父子计量和合入真实矛盾裁决，不另写缩略正文，也不做文风统一式重写。每个最终 ID 都在正文出现。

默认不生成“最值得做的三件事”。用户明确询问先处理什么，或低空间已经威胁稳定性时，可以在概览后加紧急提示；它只指向相关目录章节，不复制或替代其中的解释。用户在读懂对象用途和影响后，自行决定是否继续追问或另行授权处理。

`final/findings.json` 保留无损合并、去重和必要矛盾裁决后的完整候选，`render_report.ps1` 可生成初稿，均不能替代目录章节。`validate_report.ps1` 同时检查候选来源闭合、动作枚举、范围与只读状态、危险建议、可回收依据以及完整正文引用；它不规定标题或文风。

## 阶段 6：另行清理

审计完成不等于授权清理。执行前重新核验路径、活动状态、方法范围、影响、预计收益和恢复条件；让用户确认具体对象和动作。一次处理小批量，之后比较实际可用空间并验证相关功能。

## 降级方式

- 无子 Agent：按已经形成的 `cluster-plan` 串行调查，并说明缺少隔离上下文分工。
- 无管理员权限：受限区域保持未知，不夺权。
- 无网络：使用本机证据；只有依赖外部依据的结论才降低置信度。
- 扫描超时：退回一级目录和短名单，不把部分数据当完整结果。
- 来源不明：保留并提出最有价值的下一项核验。
